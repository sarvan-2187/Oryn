# App Lock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An optional PIN gate — locked on launch if a PIN is set, and re-locked after a configurable idle period.

**Architecture:** A `lock.ts` query module stores a salted, hashed PIN and an idle-timeout minutes value in the existing `settings` key-value table (from the Reminders feature) using Node's built-in `crypto` (scrypt) — no new table, no new dependency. A `locked` flag in the zustand store gates the whole renderer: when true, `App.tsx` renders only a `LockScreen`; a small `IdleLockWatcher` component listens for input and re-locks after N idle minutes. This is a UI-level deterrent, not encryption — the SQLite file itself stays plain, unchanged from the existing threat model documented in `FUTURE_WORK.md`.

**Tech Stack:** Node's built-in `crypto` module (`scryptSync`, `timingSafeEqual`, `randomBytes` — no new dependency), better-sqlite3, React + zustand.

## Global Constraints

- No new npm dependencies — PIN hashing uses Node's built-in `crypto`, not bcrypt or similar.
- Follow the existing IPC pattern: entries in `src/main/ipc.ts`'s `handlers` map, mirrored in `src/preload/index.ts`'s `api`, typed in `src/preload/index.d.ts`'s `OrynApi`.
- The PIN itself is never stored — only `scrypt(pin, salt)` plus the salt, as one `"salt_hex:hash_hex"` string.
- This is not full at-rest encryption. Physical access to the machine already means access to the plain SQLite file; the lock only deters a casual glance at the running app. Don't oversell it in any UI copy.
- **Deviation from the original one-line design note in `FUTURE_WORK.md`:** it said idle re-lock should "reuse the existing window-focus/activity events already wired in `index.ts`" — no such activity-tracking exists there (only tray-related `win.focus()` calls, unrelated). Idle re-lock is implemented in the renderer instead, listening for `mousemove`/`keydown`/`click` and resetting a timer — the standard approach, and simpler than routing activity through IPC from the main process.
- Tests run via `npm test`; add the new test file to the `test` script in `package.json` (both the esbuild bundle list and the `node` run list). `lock.ts` has no Electron dependency, so it's fully unit-testable, same as every other query module.

- [ ] **Step 3: Implement `src/main/db/queries/lock.ts`**

```ts
import { randomBytes, scryptSync, timingSafeEqual } from 'node:crypto'
import { getSetting, setSetting, deleteSetting } from './settings'

const PIN_KEY = 'lock.pin' // stored as "saltHex:hashHex"
const IDLE_KEY = 'lock.idleMinutes'
const DEFAULT_IDLE_MINUTES = 10
const KEY_LENGTH = 32

function hashPin(pin: string, salt: Buffer): Buffer {
  return scryptSync(pin, salt, KEY_LENGTH)
}

export function isPinSet(): boolean {
  return getSetting(PIN_KEY) !== undefined
}

/**
 * The PIN itself is never stored — only scrypt(pin, salt) alongside the
 * salt, as one "saltHex:hashHex" string. This is a UI-level deterrent, not
 * encryption; see the plan's Global Constraints.
 */
export function setPin(pin: string): void {
  const salt = randomBytes(16)
  const hash = hashPin(pin, salt)
  setSetting(PIN_KEY, `${salt.toString('hex')}:${hash.toString('hex')}`)
}

export function clearPin(): void {
  deleteSetting(PIN_KEY)
}

export function verifyPin(pin: string): boolean {
  const stored = getSetting(PIN_KEY)
  if (!stored) return false
  const [saltHex, hashHex] = stored.split(':')
  const salt = Buffer.from(saltHex, 'hex')
  const expected = Buffer.from(hashHex, 'hex')
  const actual = hashPin(pin, salt)
  return actual.length === expected.length && timingSafeEqual(actual, expected)
}

export function getIdleMinutes(): number {
  const v = getSetting(IDLE_KEY)
  return v ? Number(v) : DEFAULT_IDLE_MINUTES
}

export function setIdleMinutes(n: number): void {
  setSetting(IDLE_KEY, String(Math.max(1, Math.round(n))))
}
```

- [ ] **Step 1: Implement `src/renderer/src/components/IdleLockWatcher.tsx`**

```tsx
import { useEffect } from 'react'
import { useStore } from '../store'

const ACTIVITY_EVENTS = ['mousemove', 'keydown', 'click'] as const

/**
 * Re-locks the app after getIdleMinutes() of no mouse/keyboard input — but
 * only once a PIN is actually set; otherwise there's nothing to lock back
 * behind. Renders nothing; it's a side-effect-only component so App.tsx can
 * mount it declaratively alongside ConfirmDialog.
 */
export function IdleLockWatcher(): null {
  useEffect(() => {
    let idleTimer: ReturnType<typeof setTimeout> | null = null
    let armed = false
    let cancelled = false

    const resetTimer = async (): Promise<void> => {
      if (!armed || cancelled) return
      if (idleTimer) clearTimeout(idleTimer)
      const minutes = await window.oryn.lock.getIdleMinutes()
      if (cancelled) return
      idleTimer = setTimeout(() => useStore.getState().setLocked(true), minutes * 60_000)
    }

    const onActivity = (): void => {
      void resetTimer()
    }

    void window.oryn.lock.isSet().then((set) => {
      if (cancelled || !set) return
      armed = true
      void resetTimer()
    })

    for (const event of ACTIVITY_EVENTS) window.addEventListener(event, onActivity)

    return () => {
      cancelled = true
      for (const event of ACTIVITY_EVENTS) window.removeEventListener(event, onActivity)
      if (idleTimer) clearTimeout(idleTimer)
    }
  }, [])

  return null
}
```
