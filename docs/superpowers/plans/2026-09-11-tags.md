# Tags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shared `#tag` system across notes and tasks: typing `#word` anywhere in a note's title/body or a task's title/description tags it, and both views get a tag filter chip row to browse by tag.

**Architecture:** One `tags` table plus two join tables (`note_tags`, `task_tags`), synced on every note/task save by re-parsing `#tag` tokens out of its text and replacing its join rows (delete-then-insert — these sets are always small, so this stays simpler than diffing). `listNotes`/`listTasks` grow an optional `tagId` filter that joins through those tables. The UI adds a tag chip row above the existing list in Notes and Tasks, mirroring the pill-button style the Tasks scope tabs already use.

**Tech Stack:** better-sqlite3 (main process), React + zustand (renderer). No new dependencies.

## Global Constraints

- No new npm dependencies.
- Never edit migration index 001 — this is a real, already-migrated local database (per the comment at the top of `src/main/db/migrations.ts`). Tags are migration 002, appended to the `migrations` array.
- Follow the existing IPC pattern: one entry in `src/main/ipc.ts`'s `handlers` map, mirrored in `src/preload/index.ts`'s `api`, typed in `src/preload/index.d.ts`'s `OrynApi`.
- Backend query functions use parameterized (`?`) placeholders only, never string-concatenated user input.
- Tests run via `npm test`; add new test files to the `test` script in `package.json` (both the esbuild bundle list and the `node` run list), following `test/phase3.test.ts`'s style: `assert` + a `check(name, fn)` helper, in-memory-per-file temp DB via `ORYN_DB_PATH`.
- **Deviation from the original one-line design note in `FUTURE_WORK.md`:** that note said tags come from "note titles/task titles". In practice a note's title is usually auto-derived from its first line (see `Notes.tsx`'s `save`), so real `#tags` will actually live in the body. Tags are parsed from **title + body/description combined** for both notes and tasks, not title alone — otherwise the feature would rarely fire for notes.
- **Known limitation, not fixed here:** a recurring task's next instance is spawned via a raw `INSERT` in `toggleTask` (`src/main/db/queries/tasks.ts`) that copies title/description directly — Task 4 below closes this gap by syncing tags there too, so this isn't actually left open, but call it out since it wasn't in the original one-line spec.

```ts
import { getDb } from '../connection'
import type { Tag } from '../../../shared/types'

export type { Tag }

export function listTags(): Tag[] {
  return getDb().prepare('SELECT * FROM tags ORDER BY name').all() as Tag[]
}

/** Extracts #tag tokens from text, lowercased and deduped. */
export function parseTags(text: string): string[] {
  const matches = text.match(/#([\p{L}\p{N}_-]+)/gu) ?? []
  const names = matches.map((m) => m.slice(1).toLowerCase())
  return [...new Set(names)]
}

function upsertTagIds(names: string[]): number[] {
  if (names.length === 0) return []
  const db = getDb()
  const insert = db.prepare('INSERT INTO tags (name) VALUES (?) ON CONFLICT(name) DO NOTHING')
  const select = db.prepare('SELECT id FROM tags WHERE name = ?')
  return names.map((name) => {
    insert.run(name)
    return (select.get(name) as { id: number }).id
  })
}

/**
 * Replaces the tag set for one note with whatever #tags are currently in its
 * text. Delete-then-insert is simplest and correct — these sets are always
 * small, so diffing isn't worth the extra code.
 */
export function syncNoteTags(noteId: number, text: string): void {
  const db = getDb()
  const ids = upsertTagIds(parseTags(text))
  db.transaction(() => {
    db.prepare('DELETE FROM note_tags WHERE note_id = ?').run(noteId)
    const insert = db.prepare('INSERT INTO note_tags (note_id, tag_id) VALUES (?, ?)')
    for (const id of ids) insert.run(noteId, id)
  })()
}

export function syncTaskTags(taskId: number, text: string): void {
  const db = getDb()
  const ids = upsertTagIds(parseTags(text))
  db.transaction(() => {
    db.prepare('DELETE FROM task_tags WHERE task_id = ?').run(taskId)
    const insert = db.prepare('INSERT INTO task_tags (task_id, tag_id) VALUES (?, ?)')
    for (const id of ids) insert.run(taskId, id)
  })()
}
```

```ts
export function listTasks(
  opts: { spaceId?: number | null; scope?: Scope; date?: string; tagId?: number | null } = {}
): TaskTree[] {
  const db = getDb()
  const day = opts.date ?? today()
  const where: string[] = ['parent_id IS NULL']
  const params: unknown[] = []

  if (opts.spaceId != null) {
    where.push('space_id = ?')
    params.push(opts.spaceId)
  }

  switch (opts.scope ?? 'all') {
    case 'today':
      where.push(
        "((status != 'done' AND due_date IS NOT NULL AND due_date <= ?) OR (status = 'done' AND date(completed_at, 'localtime') = ?))"
      )
      params.push(day, day)
      break
    case 'upcoming':
      where.push("status != 'done' AND due_date > ?")
      params.push(day)
      break
    case 'someday':
      where.push("status != 'done' AND due_date IS NULL")
      break
  }

  const join =
    opts.tagId != null ? 'JOIN task_tags tt ON tt.task_id = tasks.id AND tt.tag_id = ?' : ''
  const joinParams = opts.tagId != null ? [opts.tagId] : []

  const parents = db
    .prepare(
      `SELECT tasks.* FROM tasks ${join} WHERE ${where.join(' AND ')}
       ORDER BY
         status = 'done',
         due_date IS NULL,
         due_date,
         CASE priority WHEN 'high' THEN 0 WHEN 'med' THEN 1 ELSE 2 END,
         sort_order, id`
    )
    .all(...joinParams, ...params) as Task[]

  if (parents.length === 0) return []

  const placeholders = parents.map(() => '?').join(',')
  const kids = db
    .prepare(`SELECT * FROM tasks WHERE parent_id IN (${placeholders}) ORDER BY sort_order, id`)
    .all(...parents.map((p) => p.id)) as Task[]

  return parents.map((p) => ({ ...p, children: kids.filter((k) => k.parent_id === p.id) }))
}
```
